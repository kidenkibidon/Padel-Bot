# PADEL ESCAPE

Telegram-бот для одного падел-комьюнити. Основной язык — русский, время — Asia/Dubai.
Эта ветка реализует согласованные правила ТЗ 2.3. Проверки используют тестовую базу
и имитацию Telegram; живой сервер и новый аккаунт Turso отдельно ещё не проверены.

## Что умеет бот

- Одноразовая регистрация по Telegram ID, необязательное имя, стартовый уровень.
- Профиль, личная история, итоговые места, таблица и пересчёт внутреннего рейтинга.
  B− стартует с 4.00, B — с 4.50; подробности в RATING_RULES.md.
- Создание, предпросмотр, публикация, изменение, копирование, закрытие и отмена турниров.
- Сохранение неполных черновиков и шагов мастера; корзина с восстановлением.
- Форматы: Мексикано / Американо / Social / Другой с собственным текстом.
- Календарь: сегодня и следующие 13 дней, автоматический год, ручная дата,
  затем время. Всё остаётся одним логическим шагом мастера из 12 полей.
- Вместимость 4/8/12/16/20/24, карта или Telegram pin, стоимость и валюта,
  включённые услуги, уровни, срок закрытия записи.
- Административный каталог кортов: создание, просмотр, изменение, архивирование,
  восстановление. Шаблон подставляет название, фото и карту в новый турнир.
  Старые турниры сохраняют свои снимки полей.
- Учёт оплат только для администрации, без приёма платежей и возвратов.
- Рассылки с предпросмотром, закреп регистрации, ручное управление участниками.

## Очередь без резерва

Место получает первый игрок, успешно нажавший «Иду». Ни срок 30 минут,
ни статус «Предложено место» больше не применяются. Старые резервы при
первом запуске новой версии становятся готовыми игроками очереди; старые
кнопки принятия резерва не изменяют участие.

Первый готовый игрок оповещается сразу. Если он не ответил, второй получает
сообщение через 15 минут, третий через минуту после второго и так далее.
Отказ или переход в «Не уверен» последнего уведомлённого сразу продвигает цепочку.
Ранее уведомлённые тоже могут записаться, если место ещё свободно. Неуверенные
не продвигаются автоматически. Транзакции защищают последнее место от двух заявок.

Одно активное сообщение на игрока и турнир: изменение числа свободных мест
редактирует это сообщение. После заполнения сообщение закрывается, рассылка
останавливается. Новая вакансия после заполнения запускает новую цепочку.
Состояние переживает рестарт. Неопределённый исход сетевого запроса к Telegram
между фактической отправкой и сохранением ID всё ещё может дать дубль;
абсолютной exactly-once гарантии Bot API этот код не заявляет.

## Тихие часы и активность

Напоминания за 24/12/2/1 час отправляются только с 09:00 до 22:00 по Дубаю.
Утренние сроки до 09:00 переносятся на 09:00 того же дня; вечерние после 22:00 —
на 22:00. Совпавшие сроки одного игрока и турнира объединяются. Сроки после начала,
до записи игрока или до актуального изменения расписания не догоняются.
Текст содержит точную дату, время и карту. Окно проверяется и при повторной попытке.
Время интерфейса имеет точность до минуты: отправка в минуту 22:00 разрешена,
с 22:01 — уже нет. Просрочка допустима до 15 минут, но только внутри окна и до игры.

Для уведомлений очереди ночью есть отдельное исключение: игрок готов играть
и был активен в боте не более 30 минут назад ИЛИ написал в подключённой группе
не более 5 минут назад. Проверка перед каждой отправкой. Неактивные пропускаются,
но остаются в очереди. Хранятся временные отметки, текст групповой переписки не сохраняется.
Бот должен получать обычные сообщения группы: администратор группы либо подходящая
настройка Privacy Mode. Старые сообщения не продлевают окно до времени их обработки.

## Группа без флуда

Меню команд разделено: в группе нет личных slash-команд. Регистрация и личные
разделы открываются через URL-кнопки; в карточку добавлена «Открыть бота».
Ответы на кнопки участия — всплывающие, состав редактируется в существующей
карточке. Списки и подтверждение отмены отправляются в личку. Неизвестные
групповые команды не создают сообщений. Команда /bind доступна владельцу для
подключения группы; она создаёт или обновляет регистрационный закреп.

## Фото

Фото остаются в Telegram. В базе — file_id и метаданные. Новые фото выбираются
из доступных Telegram-версий: максимальная площадь изображения при размере
не более 2 МиБ и длинной стороне не более 1600 px. Если подходящего варианта
нет, бот просит уменьшенное фото. Файлы как документы на этом шаге не принимаются.
Старые file_id автоматически не конвертируются. Копирование турнира использует
тот же file_id. Создание нового бота требует повторной загрузки; смена имени
того же бота не равна созданию нового. Важные оригиналы храните отдельно.
Фото необязательно для публикации текущей версии.

## Запуск

Нужны Python 3.11+ и системная база часовых поясов. Для установки зависимостей:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Секретные настройки хостинга или локальный закрытый .env:

```text
BOT_TOKEN=значение_из_BotFather
OWNER_ID=числовой_Telegram_ID
ADMIN_IDS=дополнительные_ID_через_запятую
GROUP_ID=ID_тестовой_группы
DB_PATH=data/padel.sqlite3
```

Не публикуйте реальные токены. Для первой локальной настройки доступен configure.py.
Проверка и запуск:

```sh
.venv/bin/python bot.py --check
.venv/bin/python bot.py
```

В группе владелец выполняет /bind; пользователи начинают с /start в личке.
Одновременно должен работать один polling-процесс для этого токена. Локальный
lock не защищает от второго сервера. Существующий webhook автоматически не удаляется.

Для VPS с systemd: sudo bash install.sh из корня проекта. Установщик требует
python3-venv, сохраняет предыдущий код, .env и стандартную папку data в закрытый
rollback-каталог на сервере перед заменой файлов. Если DB_PATH указывает вне data,
сделайте отдельную копию этой базы. Установщик не переносит базу с другого сервера.
Он обновляет файлы и использует /opt/padel-escape/venv; это отдельный ручной способ
развёртывания, здесь установщик не запускался.

## Доступность и внешний прогрев

При PORT бот слушает 0.0.0.0. GET / возвращает 200; /health возвращает 200 и ok,
если рабочий цикл успешно выполнялся за последние 120 секунд, иначе 503.
HEAD поддерживается. HTTP-проверка сама не будит спящий процесс изнутри.

Подготовлен .github/workflows/keep-awake.yml: внешний запрос примерно раз в 5 минут.
Для включения нужна переменная репозитория BOT_HEALTH_URL с HTTPS-адресом /health,
файл на default branch и включённые GitHub Actions. Пока переменная не задана,
задача пропускается. workflow_dispatch позволяет запустить проверку вручную.
Это вспомогательный best-effort вариант: GitHub может задерживать расписание,
а в публичном репозитории выключает его после 60 дней без активности.
Он не гарантирует 24/7 и точность напоминаний при задержке запуска. Для постоянной
работы без сна нужен соответствующий хостинг. Конкретный сервис и тариф не менялись.

Источники для настройки:
- https://render.com/docs/free
- https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows
- https://core.telegram.org/bots/faq

## Turso и резервные копии

Код поддержки Turso подготовлен ранее. В этой работе ключи не добавлялись,
новое облачное подключение не проверялось и миграция рабочих данных не запускалась.
Без TURSO_DATABASE_URL и TURSO_AUTH_TOKEN сохраняется локальный SQLite.
Когда заданы обе переменные, работа идёт напрямую с Turso; при ошибке облака
запрещён незаметный переход на пустую локальную базу.

Перед переносом остановить старого бота и сохранить согласованную SQLite-копию:

```sh
.venv/bin/python backup.py data/padel.sqlite3 data/manual-backup.sqlite3
```

Затем, с нужными секретами окружения, ДО первого запуска бота в пустой Turso:

```sh
.venv/bin/python migrate_turso.py data/padel.sqlite3
```

Непустая цель не перезаписывается. Миграция проверяет количество строк и связи,
сохраняет исходный файл. После запуска проверить реальное сохранение и рестарт.
Ежедневные копии хранятся в data/backups за 7 дней; на временном диске это не
независимый внешний бэкап. Ветка кода не содержит базы и секретов.
Откат к старому коду после миграций выполнять с совместимой копией данных;
возврат старой SQLite-копии может потерять поздние облачные записи.

## Проверки

```sh
.venv/bin/python -m unittest discover -p 'test_*.py' -q
```

Проверяются доменные правила, одновременные заявки, цепочка 0/15/16/17 минут,
редактирование сообщений, ночные окна 30/5 минут, тихие часы, календарь,
шаблоны и архив, миграции, восстановление сессий, HTTP heartbeat.
Новые сценарии выполняются и через официальный драйвер libSQL на локальных
файлах; это не проверка настоящего аккаунта Turso. CI добавлен в tests.yml.
